# 图集返工方案 · 给绘制端

> **这份文件是给画图的那一端看的。** 目标：修掉「角色超出格子被切掉」的问题。
> 动作编排（哪一帧看哪里、做什么）**不用重想**，沿用原来的逐格表即可 —— 这次只改**构图方式**。

---

## 1. 上次为什么会切掉

上次要求的是「一排放 4 帧的长条」，而且每批**独立生成**。这带来两个必然的结果：

1. **每批的构图互相不知道对方。** 第 2 批画的时候，看不到第 1 批角色的脚站在哪、有多大。
   于是各批之间角色的**大小、高低、左右位置**都在飘。
2. **长条要正好切在格线上。** 一批 4 帧的长条必须精确是 `4 × 192 = 768` 宽，且角色不能跨越
   内部的 192 分界线。差几个像素，角色就被切一半。

**所以这次改两件事：不定长条、不定格子。** 一帧一张图，剩下的对齐由程序做。

---

## 2. 这次怎么交付

**一帧一张 PNG，透明背景，带 alpha 通道。**

- 按动作分子目录，文件名用序号（`0.png`、`1.png`……）
- **不画长条，不画格子线，不留空位，不画背景色**
- 背景必须**完全透明**（不是白色、不是品红、不是任何实色）

```
frames/
├── idle/0.png 1.png 2.png 3.png 4.png 5.png
├── running-right/0.png … 7.png
├── running-left/0.png … 7.png
├── waving/0.png … 3.png
├── jumping/0.png … 4.png
├── failed/0.png … 7.png
├── waiting/0.png … 5.png
├── running/0.png … 5.png
├── review/0.png … 5.png
├── look-a/0.png … 7.png
└── look-b/0.png … 7.png
```

共 11 个动作、68 帧。

### 命名可以很随意

**不必为每个动作建目录。** 只要文件名里能看出是哪个动作就行，下面这些全都能认：

```
idle-0.png        idle_0.png        whale-idle-0.png      鲸鱼_待机_3.png
running-right-3.png   run-right-3.png   向右-5.png
running-4.png     running_2.png     干活-1.png
waving-0.png      挥手-2.png        jumping-1.png
failed-6.png      出错-2.png        waiting-4.png
review-5.png      look-a-3.png      look-b-3.png
```

**注意区分这两个：**

- `running-right-3.png` → 向右移动那一行
- `running-3.png` → 干活中那一行

只要写清楚是哪个动作即可，序号放最后。

## 3. 硬性规格（这次的核心，务必逐条遵守）

上次的问题就是这一节能给出的信息缺失 —— 只有一句「不要碰到边界」，而 1px 和 60px 都叫没碰到。
下面是量化后的数字。

### 画布

| 项 | 值 |
|---|---|
| 每张图的画布 | **512 × 560** |
| 画布背景 | **完全透明** |
| 画面水平中心 | **x = 256** |

### 角色在画布里的位置

| 约束 | 数值 |
|---|---|
| 脚底线（角色最低点） | **y = 544** |
| 角色最高点 | **不高于 y = 44**（即角色最高 **500 px**） |
| 角色最左 / 最右 | **不超出 x = 16 ~ 496**（即最宽 **480 px**） |
| 允许出现范围 | `x ∈ [16, 496]`、`y ∈ [44, 544]` |

### 三条必须同时成立

**① 所有帧、所有动作，角色大小必须一致。**
统一以最大的那个动作为准定比例，其余动作按**同一个比例**画。
不能出现「这一帧画得大、那一帧画得小」—— 播放时会忽大忽小，比切边还难看。

**② 脚底线固定在 y = 544 且所有帧统一。**
角色站着、走路、挥手、出错……脚底都必须落在这一条线上。
只有这样，各帧拼起来重心才不会跳。

**③ 不要为了填满画布而放大。**
`review` 只是个点头、`waiting` 只是左右张望 —— 这些动作本身就小，
**保持和其他帧同一比例**，不要单独放大去占满画布。

### 唯一的例外：`jumping`

跳跃这一行，脚可以离开 `y = 544`：

- 画布仍然是 **512 × 560**，不要改
- 腾空高度**用画布内的位置表达** —— 跳得越高，角色整体越靠上
- 最高点建议脚底约在 `y = 300` 左右
- 起跳前一帧与落地后一帧，脚底必须回到 `y = 544`

> 这一行会按整张画布对齐，所以**角色在画布里的高低就是最终的腾空高度**，会被完整保留。

## 4. 常见错误对照

| ❌ 上次的做法 | ✅ 这次要求 |
|---|---|
| 一排 4 帧拼成一条长图 | **一帧一张图，各自独立** |
| 角色顶到画布边缘 / 被画布切掉 | 四周都留透明余量（角色不超出 `x∈[16,496]`、`y∈[44,544]`） |
| 各批之间角色大小不一 | 所有帧同一比例 |
| 各批之间脚底高低不一 | 脚底统一在 `y = 544` |
| 白色 / 品红 / 灰色背景 | **完全透明**背景 |
| 画了格线、帧号、留白占位 | 都不要，一张图里只有一个角色 |
| 带投影、落地阴影、地面线 | 都不要（会被切出来变成脏边） |
| 独立的星星、闪光、速度线、残影 | 都不要 |
| 一帧里画了两个姿势做对比 | 一帧只有一个姿势 |
| 角色太小、四周空一大圈 | 按第 3 节的尺寸画，用满安全区 |

## 5. 逐帧动作编排

**沿用原来的《逐格动作与视线表》，不需要重做。** 只把「画在哪里、画多大」换成第 3 节的规格。

各行的帧数必须严格对上（第 2 节的目录清单），少一帧或多一帧都会被指出来。

## 6. 交付前的自检

出图后逐条过一遍：

- [ ] 每张都是 **512 × 560**，透明背景
- [ ] 一帧一张图，没有长条
- [ ] 角色最低点在 `y = 544`（`jumping` 行除外）
- [ ] 角色最高点不低于 `y = 44`，最左最右在 `x = 16 ~ 496` 内
- [ ] **所有帧的角色大小看起来一样**（把它们并排放在一起比）
- [ ] 角色没有一处碰到画布边缘
- [ ] 每个动作的帧数与第 2 节一致
- [ ] 没有阴影、格线、帧号、特效、文字

## 7. 拼装前的预检（这一段是给人看的，可以不给绘制端）

拿到散帧后先预演，**不写文件**，只看报告：

```bash
node tools/assemble-atlas.mjs frames/ --dry-run
```

报告会指出具体哪一帧有问题、是什么问题：

```
⚠️  发现 2 处可能的问题：
     idle/5.png：角色贴到了画布边缘，源图里可能已经被裁掉了。这一帧建议重画（四周留些余量）
     waving/0.png：整圈边框都不透明 —— 大概率是实色背景而非透明底。请确认，或用 --key 抠色
```

- **「贴到了画布边缘」** → 源图里角色已经被切了，**这一帧必须重画**
- **「整圈边框都不透明」** → 背景不是透明的，**重导出透明底**，或用 `--key <背景色>` 抠色
- **「按画布锚定的帧尺寸不一致」** → `jumping` 那几帧的画布大小不统一，腾空高度会对不齐

确认无误后再正式生成图集：

```bash
node tools/assemble-atlas.mjs frames/ --out assets/spritesheet.png
```

它会自动完成：

- **按 alpha 裁剪** —— 每帧裁到角色实际范围
- **全局统一缩放** —— 所有帧同一个比例（取最严格的那一帧）
- **底边居中** —— 水平居中，底边贴格子地面线（距格底 12px）
- **`jumping` 行按整张画布锚定** —— 保留角色在画布里的高低位置，
  即**腾空高度被完整保留**；同时用该行落地帧的最低点推算地面线，
  和其他行对齐在同一条线上（跨行播放不会整体上下跳）

> 地面线会有 ±1~2px 的误差：降采样时最外一行只覆盖部分像素，
> alpha 落到阈值以下就量不到。这不是错位。

装配完装进桌宠：

```bash
node tools/install-atlas.mjs assets/spritesheet.png --name whale --display "大肥鲸"
```
