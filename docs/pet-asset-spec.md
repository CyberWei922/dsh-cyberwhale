# 桌宠图集规格书（Codex v2 Pet 契约 · 适配版）

> 本规格基于 OpenAI `hatch-pet` skill 的 `codex-pet-contract.md` 与 `animation-rows.md`
> （Apache-2.0），用于本项目自制素材。**不包含 OpenAI 的任何美术资产。**

---

## 1. 图集几何（硬性要求）

| 项 | 值 |
|---|---|
| 格式 | PNG 或 WebP |
| 总尺寸 | **1536 × 2288** px |
| 网格 | **8 列 × 11 行** |
| 单元格 | **192 × 208** px |
| 背景 | **完全透明**（alpha 通道，不是白色） |
| 元数据 | `spriteVersionNumber: 2` |

坐标换算：第 `r` 行第 `c` 列的单元格，左上角在 `(c × 192, r × 208)`。

> **本项目已锁定：11 行完整版（1536 × 2288），含注视方向。不要提交 9 行 / 1872 高的版本。**

---

## 2. 角色尺寸与安全区（硬性）

「不要碰到格子边界」是无法执行的要求 —— 1px 和 60px 都叫"没碰到"。下面是量化后的规格。

**单元格 192 × 208 内的安全区：168 × 184**

| 约束 | 数值 | 说明 |
|---|---|---|
| 角色最大宽度 | **≤ 168 px** | 左右各留 ≥ 12 px |
| 角色最大高度 | **≤ 184 px** | 上留 ≥ 12 px |
| 脚底/重心线 | 距单元格底边 **12 px** | 即 `y = 196`，**所有帧统一** |
| 水平居中 | 以 `x = 96` 为轴线 | 左右大致对称即可 |
| 允许的像素范围 | `x ∈ [12, 180]`、`y ∈ [12, 196]` | 超出即视为越界 |

**三条必须同时满足：**

1. **统一缩放** —— 所有帧的角色用**同一个比例**。不能有的帧大、有的帧小，
   否则播放时会忽大忽小。以最大的那个动作（通常是 `jumping` 或 `failed`）为准定比例，
   其余动作按同样比例画。
2. **重心线固定** —— 除 `jumping` 行外，脚底必须都落在 `y = 196`。
   `jumping` 行允许整体上移，但**起跳前与落地后的帧仍需回到 `y = 196`**。
3. **四周留余量** —— 即使某个动作本身很小（比如 `review` 只是个点头），也**不要放大**去填满，
   保持与其他帧同一比例。

> **如果做不到以上约束，请直接交付透明底的散帧**（每个动作一个子目录，见第 7 节），
> 由 `tools/assemble-atlas.mjs` 统一裁剪、统一缩放、统一对齐。这样绘制端只需要
> 保证「角色完整、不贴边」，不需要关心网格。

## 3. 行语义

### 标准动画行（行 0–8）

| 行 | 状态 | 命名 | 用到的列 | 每帧时长 (ms) |
|---|---|---|---|---|
| 0 | 待机 | `idle` | 0–5 | 4400, 110, 110, 140, 140, 1100（每 6 秒眨眼一次） |
| 1 | 向右移动 | `running-right` | 0–7 | 120 ×7 + 末帧 220 |
| 2 | 向左移动 | `running-left` | 0–7 | 120 ×7 + 末帧 220 |
| 3 | 挥手 | `waving` | 0–3 | 按 0→1→2→1→2→1→0→3 单次播放，共 2600ms |
| 4 | 跳跃 | `jumping` | 0–4 | 140 ×4 + 末帧 280 |
| 5 | 出错/沮丧 | `failed` | 0–7 | 140 ×7 + 末帧 240 |
| 6 | 等待确认 | `waiting` | 0–5 | 150 ×5 + 末帧 260 |
| 7 | 正在干活 | `running` | 0–5 | 120 ×5 + 末帧 220 |
| 8 | 检查结果 | `review` | 0–5 | 150 ×5 + 末帧 280 |

### 注视方向行（行 9–10）

| 行 | 列 → 角度 |
|---|---|
| 9 | 000°(正上), 022.5, 045, 067.5, 090(右), 112.5, 135, 157.5 |
| 10 | 180°(正下), 202.5, 225, 247.5, 270(左), 292.5, 315, 337.5 |

两行都是**满 8 列**，顺时针连续一圈。

⚠️ **这两行是整套里最难的部分**，绘制时注意：
- 16 个姿势连起来看必须是一条**连续顺时针**的"视线轨迹"，不能是 16 张各自为政的图
- 靠**眼睛 + 头部 + 身体（必要时 + 触手/鳍/道具）**的组合来表达方向，**不要整体旋转整只角色**
- `000°` 是正上方（12 点钟），`090°` 是右，`180°` 是正下，`270°` 是左
- **不需要画正面**：正面是无向量死区，运行时会回落到 `idle`
- 可用 `measure_direction_continuity.py` 做连续性自检

## 4. 必须遵守的绘制规则

1. **透明背景**：未使用的单元格必须**完全透明**，不能留白、不能放占位方块。
2. **每行只在"用到的列"里画**。例如 `idle` 只用列 0–5，那么列 6、7 必须全透明。
3. **各帧对齐**：同一角色，脚底/重心位置应在各帧间保持一致，避免播放时抖动。
   参考：单元格 192×208，角色大致居中偏下。
4. **不要画分离的粒子/特效**（`failed` 行特别注明：要"可读的沮丧"，不要嘈杂的飞溅特效）。
5. **`running-left` 不要简单镜像 `running-right`**——除非角色本身左右对称且没有道具/手持物。
   如果有手持道具（笔记本、文件），镜像会让道具跑到错误的手上。
6. **注视方向不能靠整体旋转**：要用眼睛/头部/身体的组合动作表达方向。`000°` 是**正上方（12 点钟）**，
   不是正面；正面是"无向量死区"，会回落到 `idle`，所以**不需要单独画正面帧**。
7. `idle` 的第一帧同时充当**减弱动效模式**下的静态帧，所以它必须是一张完整的、可独立成立的造型。

## 6. 自检清单（出图后逐条过）

- [ ] 总尺寸精确 1536×2288
- [ ] 每格精确 192×208，无 1px 偏移
- [ ] 背景透明，无白底/黑底残留
- [ ] 未使用单元格全透明
- [ ] `idle` 只用列 0–5，列 6–7 透明
- [ ] 逐行播放动画时无跳帧、无抖动、重心稳定
- [ ] `running-left` 的道手/道具方向正确
- [ ] 注视方向是连续顺时针一圈，且 `000°` 朝上
- [ ] **角色外接框 ≤ 168 × 184**（在第 2 节的安全区内）
- [ ] **各帧脚底都落在 `y = 196`**（`jumping` 行除外）
- [ ] **各帧角色大小一致**（没有忽大忽小）
- [ ] 边缘无被裁切（角色四周都留有透明余量，没有顶到 192×208 的边界）
- [ ] 导出为带 alpha 的 PNG 或 WebP（**不要** JPEG）

## 7. 生产工具（可直接用）

### 本项目自带：散帧 → 图集

**`tools/assemble-atlas.mjs`** —— 把透明底散帧拼成符合本规格的图集。推荐优先用它。

```bash
# 帧目录按动作分子目录：frames/idle/0.png、frames/running-right/0.png ...
node tools/assemble-atlas.mjs frames/ --out assets/spritesheet.png

# 先预演，只看报告不写文件
node tools/assemble-atlas.mjs frames/ --dry-run

# 源图是实色底（没有 alpha 通道）时抠色
node tools/assemble-atlas.mjs frames/ --key FF00FF
```

它负责第 2 节里那些硬性约束：按 alpha 自动裁剪、**全局统一缩放**、**底边居中**
对齐到 `y = 196`。所以绘制端只要给出「角色完整、不贴边」的透明散帧即可，
不需要自己对齐网格。

报告里会明确指出两类源图问题：

- **源文件没有 alpha 通道**（实色背景）→ 需要透明底或 `--key`
- **角色贴到了画布边缘** → 源图里可能已经被裁掉了，这一帧建议重画

### 参考：`hatch-pet` skill 自带的 Python 脚本

`hatch-pet` skill 自带一套 Python 脚本（Apache-2.0），可用来确定性拼装与校验图集：

- `compose_atlas.py` — 按格拼装图集
- `extract_strip_frames.py` — 从横向长条切帧
- `inspect_frames.py` — 校验行/列/透明规则
- `derive_running_left_from_running_right.py` — 派生左向行
- `make_contact_sheet.py` / `make_direction_qa_sheet.py` — 生成目检图
- `measure_direction_continuity.py` — 注视方向连续性检查
